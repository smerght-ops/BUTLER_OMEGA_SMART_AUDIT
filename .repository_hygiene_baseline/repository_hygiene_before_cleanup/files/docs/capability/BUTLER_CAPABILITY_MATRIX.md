# BUTLER OMEGA SMART — Capability Matrix

Статус: аналитический документ, Stage 1  
Дата: 14.07.2026  
Основание: фактическая реализация `execute()` зарегистрированных обработчиков Butler.

## 1. Границы исследования

В карту включены только компоненты, реально зарегистрированные в `SmartDispatcherV2`, а также штатный CHAT fallback. Название класса и декларация `CAPABILITIES` сами по себе не считались доказательством: возможность включена только тогда, когда соответствующее действие реализовано в `execute()` или в непосредственно вызываемом им рабочем компоненте.

Каталоги `ChatDepartment`, `ExternalDepartment`, `OCRDepartment` и `VoiceDepartment` содержат только `__init__.py`, не имеют собственного `runner.py` с `execute()` и не зарегистрированы как самостоятельные исполнители. Поэтому отдельные возможности им не приписываются. CHAT фактически реализован через `SmartDispatcher._execute_chat()` и локальный Ollama-провайдер.

Текущая модель выполнения — один Department на один пользовательский запрос. Цепочки ниже означают последовательность запросов пользователя и передачу результата/ссылки через существующий контекст. Автоматического workflow, который сам вызывает несколько Department подряд, в исследованном контуре нет.

## 2. Реальные возможности по исполнителям

### IMAGE

- создаёт новое PNG-изображение по текстовому описанию через ComfyUI;
- строит и рецензирует Stable Diffusion prompt;
- поддерживает продолжение текущей сессии генерации и уточнение prompt;
- поддерживает специальные ограничения для гибридных объектов;
- сохраняет итоговый prompt и PNG;
- пытается открыть готовый PNG через Windows Shell.

Не подтверждено: редактирование переданного пользователем существующего изображения. Продолжение IMAGE создаёт новую генерацию на основе накопленного prompt, а не изменяет исходный bitmap.

### VISION

- анализирует существующие PNG/JPG/JPEG/WEBP/BMP-изображения;
- описывает объекты, сцену и визуальные признаки;
- распознаёт видимый текст (OCR посредством vision-модели);
- возвращает контролируемые ошибки отсутствующего и неподдерживаемого файла.

### VIDEO

- проверяет путь и формат видео;
- извлекает репрезентативные кадры через OpenCV;
- анализирует последовательность кадров vision-моделью;
- описывает объекты, действия и изменения в MP4/AVI/MOV/MKV/WEBM;
- диагностирует отсутствующий файл, неподдерживаемый формат, ошибку движка и пустой ответ.

### AUDIO

- передаёт текст настроенному движку синтеза речи;
- передаёт аудиофайл настроенному движку распознавания речи;
- проверяет наличие входного аудиофайла;
- возвращает контролируемую диагностику, если движок отсутствует или ответ пуст.

Фактическое ограничение: собственного TTS/STT-движка Department не содержит; полезный результат зависит от callable `audio_engine` в context.

### ARCHIVE

- создаёт ZIP из файла или каталога;
- создаёт TAR;
- создаёт GZ для одного файла;
- распаковывает ZIP/TAR/GZ;
- пытается распаковывать RAR/7Z через доступный системный механизм;
- проверяет существование источника и допустимость формата.

Фактическое ограничение: запись RAR/7Z без настроенного системного инструмента не реализована.

### CODING

- генерирует PowerShell, Python и Bash;
- генерирует функции, классы и скрипты;
- объясняет код, если это явно запрошено;
- предлагает исправление кода и ошибок;
- проверяет релевантность результата для поддержанных классов запросов;
- выполняет fallback по цепочке локальных моделей;
- возвращает управляемую ошибку, если все ответы нерелевантны.

Не подтверждено: фактический запуск созданного кода, изменение файлов проекта или применение патчей.

### TEXT

- переводит пользовательский текст;
- перефразирует текст;
- исправляет грамматику;
- создаёт текст, письмо, описание, план, рапорт или отчёт;
- объясняет и формулирует текстовый материал;
- очищает ответ модели от служебных рассуждений.

Не подтверждено: автоматическая запись результата в файл.

### DOCUMENTS

- извлекает текст из TXT, MD и LOG;
- извлекает текст из DOCX;
- читает CSV и XLSX через spreadsheet handler;
- извлекает текст из PDF;
- для большого текста или явного запроса создаёт локальную сводку/выжимку;
- при недоступности LLM возвращает извлечённый сырой текст с диагностикой отката.

Не подтверждено: редактирование или сохранение изменений в документе.

### SEARCH

- выполняет полнотекстовый поиск в локальном каталоге;
- ищет документы и изображения по индексированным данным;
- возвращает список результатов с путями и идентификаторами;
- сохраняет результаты поиска в контексте сессии;
- при отсутствии каталожного результата ищет подходящий факт в профиле памяти.

Не подтверждено: поиск в интернете и произвольный обход всей файловой системы вне каталога.

### OPEN_DOCUMENT

- разрешает ссылку вида «первый/второй/последний файл» из контекста предыдущего SEARCH;
- проверяет наличие, тип и расширение файла;
- открывает TXT/MD/LOG/DOCX/CSV/XLSX/PDF/JPG/JPEG/PNG/WEBP штатным Windows Shell.

Не подтверждено: открытие произвольного пути без контекста поиска; изменение открытого файла.

### MEMORY

- сохраняет именованный факт в долговременный профиль;
- заменяет ранее сохранённое значение ключа;
- извлекает факт по запросу «какой мой…»;
- сообщает имя и любимый цвет, если они сохранены;
- формирует сводку сохранённых персональных данных;
- отвечает на подтверждённые запросы о возможностях, Department, состоянии проекта и архитектуре памяти из проектных артефактов;
- записывает события сессии и семантически индексирует сохранённый факт.

### HOME

- создаёт домашнее напоминание или задачу;
- изменяет и закрывает напоминание по ID;
- ведёт список покупок/домашних запасов;
- ставит на контроль срок страховки, медицинской карты и другого домашнего документа;
- показывает домашнюю сводку и срочные дела;
- регистрирует локальную программу;
- запускает зарегистрированную программу только после подтверждения в context;
- сообщает локальную идентичность Butler.

### GOAL_MANAGER

- создаёт, получает, перечисляет, обновляет и удаляет цели;
- добавляет задачи в активную цель;
- изменяет статус задачи;
- вычисляет прогресс цели и временную шкалу;
- рассчитывает приоритет задач, выдаёт приоритетный список и следующую задачу;
- создаёт, получает и оптимизирует план цели;
- создаёт, перечисляет, проверяет и подтверждает системные напоминания для задач.

Интерфейс фактически командный: `goal ...`, `plan ...`, `progress ...`, `priority ...`, `reminder ...`.

### PROJECT_DOCUMENTATION

- строит инженерный каталог проектных объектов и evidence;
- формирует инженерный отчёт о проекте;
- запускает Project Evidence Doctor в режимах status, rebuild, audit, plan, apply и confirm;
- отвечает на запросы о статусе, архитектуре, документации и roadmap проекта.

### CHAT

- отвечает на общие информационные вопросы локальной LLM;
- объясняет понятия и даёт инструкции;
- поддерживает продолжение предыдущего CHAT-сценария через ConversationContext;
- очищает пользовательский ответ от внутренних рассуждений.

Не подтверждено: выполнение действий на компьютере. CHAT сообщает инструкции, но не создаёт файлы, не запускает команды и не изменяет внешнее состояние.

## 4. Task Matrix: возможные пользовательские цепочки

Цепочки со стрелкой не означают автоматический вызов следующего Department. Пользователь выполняет следующий запрос, передавая файл, результат или ссылку из предыдущего шага.

| Пользовательская задача | Реально возможная цепочка | Условие/ограничение |
|---|---|---|
| Найти PDF и открыть его | SEARCH → OPEN_DOCUMENT | открытие по номеру результата в той же сессии |
| Найти изображение и открыть его | SEARCH → OPEN_DOCUMENT | файл должен быть в каталоге |
| Найти документ и прочитать содержимое | SEARCH → DOCUMENTS | путь из результата передаётся DOCUMENTS |
| Найти PDF и получить сводку | SEARCH → DOCUMENTS | запрос DOCUMENTS должен содержать путь и «сводка» |
| Найти изображение и описать его | SEARCH → VISION | путь передаётся VISION |
| Найти изображение и прочитать текст | SEARCH → VISION | OCR vision-моделью |
| Найти видео и описать его | SEARCH → VIDEO | видео должно быть индексировано и иметь поддержанный формат |
| Найти аудио и распознать речь | SEARCH → AUDIO | нужен настроенный audio engine |
| Найти архив и распаковать | SEARCH → ARCHIVE | путь передаётся ARCHIVE |
| Прочитать документ и перевести фрагмент | DOCUMENTS → TEXT | извлечённый текст передаётся вручную |
| Прочитать документ и перефразировать фрагмент | DOCUMENTS → TEXT | ручная передача текста |
| Прочитать документ и исправить грамматику | DOCUMENTS → TEXT | ручная передача текста |
| Прочитать техническое задание и получить код | DOCUMENTS → CODING | задача/фрагмент передаётся CODING |
| Сгенерировать код и получить объяснение | CODING → CODING | второй запрос с кодом или сохранённым контекстом |
| Сгенерировать текст и озвучить его | TEXT → AUDIO | нужен настроенный TTS engine |
| Сгенерировать описание сцены и изображение | TEXT → IMAGE | текст передаётся как prompt |
| Создать изображение и проанализировать результат | IMAGE → VISION | путь сохранённого PNG передаётся VISION |
| Создать изображение и уточнить композицию | IMAGE → IMAGE | работает ImageSession; создаётся новая генерация |
| Создать изображение и упаковать его | IMAGE → ARCHIVE | путь PNG передаётся ARCHIVE |
| Проанализировать видео и перефразировать описание | VIDEO → TEXT | описание передаётся вручную |
| Распознать речь и отредактировать текст | AUDIO → TEXT | нужен STT engine, затем ручная передача текста |
| Распаковать архив и прочитать документ | ARCHIVE → DOCUMENTS | пользователь выбирает извлечённый файл |
| Распаковать архив и проанализировать изображение | ARCHIVE → VISION | пользователь выбирает извлечённое изображение |
| Распаковать архив и проанализировать видео | ARCHIVE → VIDEO | пользователь выбирает извлечённое видео |
| Найти факт и использовать его в тексте | MEMORY/SEARCH → TEXT | значение передаётся TEXT |
| Сохранить результат как факт | TEXT/CHAT/CODING → MEMORY | требуется команда с ключом и значением, не файл |
| Создать цель и добавить задачу | GOAL_MANAGER → GOAL_MANAGER | командный интерфейс `goal ...` |
| Создать цель, построить план и выбрать следующий шаг | GOAL_MANAGER → GOAL_MANAGER → GOAL_MANAGER | `goal create` → `plan generate` → `priority next` |
| Добавить задачу, поставить напоминание и отметить выполнение | GOAL_MANAGER → GOAL_MANAGER → GOAL_MANAGER | task ID/`latest` передаются следующим командам |
| Создать домашнее напоминание и позже закрыть его | HOME → HOME | используется REM-ID |
| Зарегистрировать программу и запустить её | HOME → HOME | запуск требует `context.confirmed=True` |
| Получить проектный статус и перефразировать отчёт | PROJECT_DOCUMENTATION → TEXT | отчёт передаётся TEXT |
| Получить инженерный отчёт и найти сведения в нём | PROJECT_DOCUMENTATION → TEXT/CHAT | отдельного поиска внутри отчёта нет |
| Получить общий совет и сохранить ключевой факт | CHAT → MEMORY | пользователь формирует именованный факт |
| Получить инструкцию и создать напоминание о выполнении | CHAT → HOME | действие вручную переводится в напоминание |

### Цепочки, которые сейчас невозможны полностью

- SEARCH → OPEN_DOCUMENT → редактирование → сохранение: нет редактора документов.
- DOCUMENTS → TEXT → запись нового DOCX/PDF: нет экспорта пользовательского текста в документ.
- CHAT/CODING → выполнение shell-команды: нет безопасного executor пользовательских команд.
- IMAGE/VISION → редактирование исходного изображения: IMAGE не принимает bitmap как вход для image-to-image.
- Любая цепочка → автоматический следующий Department: общего автоматического workflow нет.

## 5. Missing Capabilities

### Файловая система

- создать папку/каталог;
- создать пустой или текстовый файл;
- записать сгенерированный текст в указанный файл;
- копировать файл или каталог;
- переместить файл или каталог;
- переименовать файл или каталог;
- удалить файл или каталог;
- перечислить содержимое произвольной папки;
- получить свойства файла и свободное место;
- безопасно создать несколько каталогов по структуре.

### Документы и данные

- редактировать существующий TXT/MD/DOCX/PDF/XLSX;
- создавать DOCX, PDF или XLSX из пользовательского текста/данных;
- объединять и разделять PDF;
- конвертировать документы между форматами;
- сохранять перевод или сводку рядом с исходным документом;
- выполнять структурные операции с таблицами, а не только извлекать данные.

### Изображения и медиа

- редактировать существующее изображение (image-to-image/inpainting);
- обрезать, масштабировать или конвертировать изображение детерминированно;
- извлекать аудиодорожку из видео;
- монтировать или конвертировать видео;
- работать с аудио без внешнего callable engine;
- сохранять транскрипцию в файл.

### Система и приложения

- выполнять разрешённые shell/PowerShell-команды пользователя;
- управлять процессами и службами;
- устанавливать программы;
- управлять окнами приложений;
- открывать произвольный известный путь без предварительного SEARCH;
- получать безопасный список файлов Desktop/Documents/Downloads.

### Информация и интеграции

- искать в интернете;
- получать актуальную погоду, новости, курсы и расписания;
- отправлять email или сообщения;
- работать с календарём и внешними задачами;
- загружать/выгружать файлы в облачные хранилища.

### Оркестрация

- автоматически выполнять многошаговую цепочку Department;
- передавать структурированный результат одного Department следующему без нового запроса;
- откатывать составную пользовательскую операцию;
- запрашивать подтверждение и затем автоматически продолжать произвольный сценарий.

## 6. Минимальные пути реализации без перепроектирования

Ниже приведены варианты, но ни один из них в рамках Stage 1 не реализуется.

| Missing Capability | Наиболее простой путь в текущей архитектуре |
|---|---|
| Создание/копирование/перемещение/переименование файлов и папок | новый узкий `FileSystemDepartment` с allowlist путей и подтверждением разрушительных операций |
| Запись текста в TXT/MD | расширение будущего `FileSystemDepartment`, а не TEXT: TEXT генерирует содержание, файловый исполнитель записывает |
| Создание DOCX/PDF/XLSX | новый `DocumentExportDepartment` либо строго ограниченное расширение DOCUMENTS отдельными create-командами |
| Редактирование документов | расширение DOCUMENTS только после определения поддерживаемых операций и форматов |
| Image-to-image/inpainting | локальное расширение IMAGE с явным входным изображением и отдельным ComfyUI workflow |
| Детерминированные операции с изображением | отдельный небольшой image utility Skill/Department; не смешивать с генеративным IMAGE |
| Полноценный TTS/STT | подключить существующий callable `audio_engine`; структура AUDIO уже предусматривает этот контракт |
| Конвертация/монтаж видео | расширение VIDEO через локальный FFmpeg с allowlist операций |
| Выполнение пользовательского кода | отдельный sandboxed execution Department; CODING должен оставаться генератором, а не исполнителем |
| Интернет-поиск | отдельный External/Search provider с явной политикой сети и источников |
| Email/календарь/облако | отдельные интеграционные Department/Skills с учётными данными и подтверждением внешних действий |
| Автоматические цепочки | отдельное последующее архитектурное решение; не добавлять в существующие Department скрытые взаимные вызовы |

## 7. Одна возможность с максимальным приростом пользы

### Безопасное управление локальными файлами и папками

Рекомендуемая следующая возможность: выполнять базовые операции с локальной файловой системой — прежде всего создавать папки и текстовые файлы, затем копировать, перемещать и переименовывать их в разрешённых пользовательских каталогах.

Почему это максимальный прирост:

1. Она закрывает уже подтверждённый реальный запрос «создай на рабочем столе папку стихотворения».
2. Она превращает результаты TEXT, CHAT и CODING из ответов на экране в сохраняемые пользовательские артефакты.
3. Она связывает существующие SEARCH, DOCUMENTS, IMAGE и ARCHIVE с реальными операциями над найденными и созданными файлами.
4. Она полезна ежедневно и не зависит от качества генеративной модели.
5. Она укладывается в утверждённую архитектуру как один узкий исполнитель и не требует изменения Dispatcher, Harness или Result Contract.

Минимальный безопасный вариант:

- один новый `FileSystemDepartment`;
- только явно перечисленные операции;
- разрешённые корни: Desktop, Documents, Downloads и workspace либо ещё более узкий allowlist;
- нормализация и проверка итогового абсолютного пути;
- запрет выхода за разрешённые корни;
- создание папки и файла без подтверждения только внутри разрешённых корней;
- обязательное подтверждение для удаления, перезаписи и перемещения существующих данных;
- отсутствие произвольного shell;
- сохранение действующего Result Contract;
- локальные пользовательские тесты на успех, конфликт имени, отсутствующий источник, запрещённый путь и отменённое подтверждение.

## 8. Итог

Butler уже уверенно решает специализированные задачи генерации и анализа медиа, обработки текста и документов, локального поиска, памяти, архивов, целей и домашних напоминаний. Главный практический разрыв находится между «сформировать ответ/артефакт» и «организовать этот артефакт в пользовательской файловой системе».

Следующий рекомендуемый Stage: отдельное техническое задание на безопасное управление локальными файлами и папками. На текущем Stage никакая реализация не выполнялась.
