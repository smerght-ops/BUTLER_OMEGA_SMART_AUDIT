============================================================
1. ГЛАВНАЯ ЦЕЛЬ
============================================================

Создать над существующими исполнительными возможностями Butler
локальный Agent Core.

Пользователь должен ставить задачу обычным человеческим языком.

Локальная LLM должна:
- понимать цель пользователя;
- учитывать предыдущий контекст;
- видеть доступные инструменты Butler;
- самостоятельно выбирать следующий инструмент;
- получать результат выполнения;
- использовать результат в следующем действии;
- продолжать работу до получения законченного результата.

Пользователь НЕ обязан знать:
TaskDecomposer,
CapabilityRegistry,
Department,
action,
intent,
tool contract
или внутреннюю архитектуру Butler.

============================================================
4. РОЛЬ СУЩЕСТВУЮЩИХ DEPARTMENTS
============================================================

Существующие Departments становятся исполнительными инструментами
для Agent Core.

Принцип:

Agent Core думает и управляет.

Departments выполняют.

Специализированные модели остаются специалистами.

Примеры:

DOCUMENTS -> документы
FILESYSTEM -> файловые операции
SEARCH -> поиск
MEMORY -> память
CODING -> специализированная кодовая модель
VISION -> vision-модель
IMAGE -> ComfyUI / генерация изображений
AUDIO -> аудио / голос
VIDEO -> видеопайплайн

Центральная LLM НЕ должна самостоятельно заменять эти системы.

5. ЭТАЛОН ПОВЕДЕНИЯ
============================================================

Bionic используется только как поведенческий эталон.

Подтверждённый эталонный сценарий:

1. Пользователь обсуждает варианты маршрута Лондон -> Париж.
2. Агент сохраняет контекст разговора.
3. Пользователь говорит:

"Создай мне Word-документ по тем вариантам маршрута
из Лондона в Париж, которые ты предложил выше.
Оформи их понятно и аккуратно и сохрани готовый
документ на рабочий стол."

4. Агент самостоятельно:
   - понимает ссылку на предыдущий контекст;
   - получает необходимые данные;
   - формирует содержимое;
   - выбирает инструмент создания документа;
   - создаёт DOCX;
   - сохраняет его;
   - возвращает готовый артефакт.

Этот сценарий является BUTLER AGENT CORE TEST №1.

============================================================

Не дублировать существующий DOCX engine.

9. ЭТАП 4 — BUTLER AGENT CORE TEST №1
============================================================

Запрещено создавать специальные правила для:

TEST №1 = FAIL.

До PASS к массовому подключению Departments НЕ переходить.

============================================================
15. ИССЛЕДОВАТЕЛЬСКИЙ РЕЗЕРВ ПОСЛЕ АТТЕСТАЦИИ AGENT CORE
============================================================
Этот раздел НЕ изменяет текущую последовательность ROADMAP.
К реализации перечисленных механизмов переходить только после
завершения основной аттестации Agent Core и его Departments.

15.1. RAMBLE / WHISPER / VOXTRAL — «ПОТОК МЫСЛЕЙ»

Исследовать локальный голосовой вход:
длинный свободный голосовой поток пользователя
→ локальное распознавание речи
→ Agent Core
→ выделение цели, контекста и ограничений
→ выполнение задачи.

Предусмотреть два специализированных аудиодвижка:
Whisper — точная локальная транскрипция записанных аудиофайлов;
Voxtral Realtime — распознавание / обработка живой речи в реальном времени.

Целевая исследовательская цепочка:
микрофон / аудиофайл
→ FFmpeg
→ Whisper / Voxtral Realtime
→ исходная стенограмма
→ Qwen 3.5 / Agent Core
→ смысловая декомпозиция
→ идеи / задачи / решения / вопросы / напоминания / проекты / факты
→ существующая Memory Butler.

Обязательно сохранять два независимых слоя:
1. RAW TRANSCRIPT — неизменяемая исходная стенограмма речи пользователя.
2. DERIVED KNOWLEDGE — производная смысловая структура, созданная LLM.

Производное знание НЕ должно заменять или изменять исходную стенограмму.

Критическое правило безопасности намерения:
мысль, предположение, идея, возможная задача и явная команда пользователя
являются разными сущностями.
Фраза, обнаруженная внутри свободного потока мыслей,
НЕ является автоматически разрешением Agent Core на выполнение действия.

Не создавать отдельную архитектуру вместо Agent Core.
Whisper и Voxtral являются специализированными инструментами AudioDepartment,
а смысловая обработка и принятие решения остаются ответственностью Agent Core.
15.2. COMPILED KNOWLEDGE / LLM WIKI

STATUS:
✅ BASELINE IMPLEMENTED
✅ PRODUCTION E2E PASS — 28.07.2026

Подтверждён production-контур:

Microphone
→ WAV
→ Whisper
→ immutable RAW TRANSCRIPT
→ DKICompiler
→ typed DERIVED KNOWLEDGE
→ existing SemanticMemory / MEMORY_INDEX

Подтверждено:
- RAW TRANSCRIPT сохраняется отдельно и не изменяется;
- DERIVED KNOWLEDGE не заменяет RAW;
- RAW ≠ COMMAND;
- обнаруженная мысль не является разрешением на выполнение;
- DKI записывается в существующую Memory Butler;
- отдельное хранилище памяти не создано;
- UTF-8 end-to-end подтверждён реальным голосовым E2E.

Дальнейшее развитие 15.2 может включать связи,
сущности, противоречия и повторное использование Agent Core,
не заменяя существующий Memory Brain.

15.3. MEMORY LINT
Исследовать периодическую проверку накопленной памяти на:
- противоречия;
- устаревшие сведения;
- отсутствующие связи;
- потерянные знания;
- пробелы в знаниях.

Memory Lint должен проверять качество существующей памяти,
а не создавать параллельное хранилище.

15.4. LLM COUNCIL
Исследовать дополнительный экспертный режим для задач,
где цена ошибки высока:

сложная задача
→ несколько специализированных моделей
→ независимые решения / критика
→ синтез
→ итоговое решение Agent Core.

Не использовать Council как обязательный маршрут обычных задач.

15.5. ОБЩИЙ ПРИНЦИП
RAMBLE → COMPILE → LINT.

Пользователь свободно формулирует мысли.
Butler преобразует их в задачу и накопленное знание.
Накопленное знание периодически проверяется на качество.

Все механизмы раздела 15 являются ИССЛЕДОВАТЕЛЬСКИМ РЕЗЕРВОМ.
Их наличие не является условием текущей аттестации Agent Core.

15.6. INDUSTRIAL CAPABILITY MAP

Статус: ИССЛЕДОВАТЕЛЬСКИЙ РЕЗЕРВ.
Не изменяет текущую последовательность ROADMAP.

Будущие профессиональные возможности Butler:

1. ENGINEERING COMPLIANCE
Agent Core понимает объект и цель проверки.
Нормативная база и validator дают проверяемый результат.
Требуется трассировка:
требование → источник → объект → PASS / FAIL / evidence.

2. COSTING / ВОР / СМЕТЫ
Agent Core извлекает структуру задания и управляет расчётом.
Источником числовой истины являются проверяемые базы расценок,
математический engine и существующие инструменты Excel.

3. BIM / CAD ORCHESTRATOR
Agent Core преобразует человеческое ТЗ в параметры и tool calls.
Исполнение выполняют специализированные BIM/CAD-системы:
IFC / Revit / Dynamo / FreeCAD / Grasshopper / API
или иные подключённые детерминированные инструменты.

4. CONSTRUCTION CV
Фото / видео / point cloud
→ специализированный CV / photogrammetry engine
→ сопоставление с BIM / проектом
→ измеримые отклонения
→ Agent Core
→ понятный пользователю результат.

5. ANALYTICS
Excel / BI / отчёты / графики являются общим выходным слоем
для Compliance, Costing, BIM/CAD и Construction CV.

ОБЩИЙ ИНВАРИАНТ:

Agent Core управляет.
Departments и специализированные engines выполняют.
LLM НЕ подменяет нормативную базу, сметный расчёт,
геометрический движок, измерительный алгоритм или CV engine.

15.7. LEARNING LOOP / RECORD SKILL

Статус: ИССЛЕДОВАТЕЛЬСКИЙ РЕЗЕРВ.

Цель:
позволить пользователю показать Butler способ выполнения работы,
после чего сохранить повторяемый способ как Skill.

Принцип:

MEMORY = ЧТО Butler знает.
SKILL = КАК Butler умеет делать.

Целевая схема:

RECORD
→ экран + действия + голос
→ понимание цели и шагов
→ SKILL COMPILER
→ GOAL + STEPS + TOOLS + CHECKS
→ Skill Library
→ Agent Core
→ существующие Departments.

Skill НЕ должен создавать параллельную исполнительную архитектуру.

Предпочитать семантические действия через существующие tools,
API, DOM, Capability Layer и Departments.

Не сохранять хрупкие координаты экрана как основной способ
автоматизации, если действие можно выразить семантически.

Learning Loop не смешивать с L1–L6 Memory.
Memory хранит знания и контекст.
Skill хранит воспроизводимый способ выполнения работы.
