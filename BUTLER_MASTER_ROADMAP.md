# BUTLER MASTER ROADMAP
## Единая инженерная дорожная карта проекта Butler Omega Smart

**Версия:** 1.0
**Дата утверждения:** 2026-07-14
**Статус:** Единственная действующая дорожная карта проекта.

После утверждения изменения в документ не вносятся.
Разрешается только отмечать выполненные этапы.

---

## ГЛАВНЫЙ ПРИНЦИП

Мы больше не строим Butler вокруг возможностей LLM.
Мы строим Butler вокруг пользовательских задач.

LLM является лишь одним из инструментов системы.
Главной единицей архитектуры становится не модель, а гарантированное выполнение пользовательской задачи.

## ГЛАВНЫЙ ВЫВОД

Архитектура Butler жизнеспособна.
Проблемой являются отдельные Department.

Dispatcher доказал свою работоспособность.
Result Contract доказал свою работоспособность.

Department можно улучшать независимо друг от друга.
Полная переделка Butler запрещается.

---

## ЧТО ЗАПРЕЩЕНО

Запрещается:

- переписывать ядро;
- менять Result Contract;
- менять Dispatcher без доказанного дефекта;
- менять архитектуру из-за одной модели;
- строить решения вокруг галлюцинаций LLM;
- выполнять массовые рефакторинги.

---

## ОСНОВНАЯ СТРАТЕГИЯ

Использовать слабые стороны моделей как входные данные для улучшения архитектуры.
Если модель ошибается — исправляется не Butler, а механизм работы Butler с моделью.

## ДОРОЖНАЯ КАРТА

### ЭТАП 1
Полностью завершён.
Аттестация всех Department.
**Статус: DONE**

### ЭТАП 2
Полностью завершён.
Исправление критических дефектов маршрутизации.
**Статус: DONE**

### ЭТАП 3
**Knowledge Layer**
Цель: убрать генерацию там, где уже существует готовое решение.
Создаются: RecipeEngine, Recipe Library, Template Library, Knowledge Registry, Definition Registry.
Acceptance: LLM сначала ищет готовое решение. Если найден рецепт — LLM не генерирует код.

### ЭТАП 4
**Coding Recovery**
Создаются: CodingValidator, ExecutionSandbox, FeedbackLoop, RetryEngine.
Acceptance: LLM никогда не отдаёт пользователю непроверенный код.

### ЭТАП 5
**Intent Layer**
Удаляется логика can_handle. Вводится единый IntentDetector.
Dispatcher работает только через Intent.
Acceptance: каждый запрос имеет единственный Intent.

### ЭТАП 6
**Skill Layer**
Coding перестаёт быть одним большим Department.
Создаются Skills: PowerShell Skill, Python Skill, SQL Skill, Regex Skill, JSON Skill, CSV Skill.
Acceptance: каждый Skill отвечает только за свою область.

### ЭТАП 7
**Execution Layer**
Любой сгенерированный код сначала проверяется.
Потом выполняется в Sandbox.
Потом оценивается.
Только после этого возвращается пользователю.

### ЭТАП 8
**Model Independence**
Butler перестаёт зависеть от одной модели.
Каждый Department может иметь собственную цепочку моделей.
При необходимости используется внешний API.

### ЭТАП 9
**Continuous Acceptance**
После каждого изменения автоматически запускается пользовательская аттестация.
Любой FAIL запрещает принимать изменения.

### ЭТАП 10
**Engineering Growth**
Расширяется библиотека рецептов.
Расширяются Skills.
Добавляются новые Department.
Архитектура при этом не меняется.

---

## ПРАВИЛА РАЗРАБОТКИ

Каждый новый механизм должен:

- не ломать существующую архитектуру;
- иметь собственную аттестацию;
- иметь собственный Result Contract;
- иметь возможность полного удаления;
- не изменять другие Department без необходимости.

---

## ПРАВИЛА ДЛЯ CODEX

Codex запрещается:

- массовый рефакторинг;
- самовольная смена архитектуры;
- изменение Dispatcher без доказательств;
- изменение Result Contract.

Codex обязан:

- решать одну задачу за раз;
- показывать изменённые файлы;
- проходить py_compile;
- проходить пользовательскую аттестацию;
- останавливаться после завершения задачи.

---

## ПРАВИЛО ПРИНЯТИЯ ИЗМЕНЕНИЙ

Изменение считается завершённым только после прохождения:

1. py_compile
2. Unit Test
3. Регрессионных тестов
4. Пользовательской аттестации через штатный Butler

Если хотя бы один этап не пройден — изменение считается непринятым.

---

## ГЛАВНОЕ ПРАВИЛО ПРОЕКТА

Мы больше не улучшаем ответы моделей.
Мы улучшаем архитектуру Butler.

Любая модель является заменяемым инструментом.
Архитектура Butler является постоянной.
