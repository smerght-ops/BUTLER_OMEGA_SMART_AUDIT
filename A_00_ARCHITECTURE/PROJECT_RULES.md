# PROJECT RULES
## Единый свод технических правил BUTLER_OMEGA

### 1. Кодировка
- Все текстовые файлы проекта сохраняются в UTF-8 БЕЗ BOM.
- Не смешивать UTF-8, UTF-8 BOM, ANSI, OEM и другие кодировки.
- Для записи через .NET использовать UTF8Encoding(false).

### 2. JSON
- user_profile.json является единственным источником пользовательских фактов.
- В JSON запрещено записывать Markdown, комментарии и произвольный текст.
- Перед чтением JSON необходимо убедиться, что файл содержит корректный JSON.

### 3. Память
- user_profile.json → источник истины.
- USER_MEMORY.md → автоматически генерируется из user_profile.json.
- MEMORY.md → только конституция, архитектурные правила и неизменяемые принципы.
- Не редактировать USER_MEMORY.md вручную.

### 4. PowerShell
- Все блоки должны быть полностью готовы к копированию и запуску.
- Запрещено выдавать незавершённые конструкции:
  - if
  - else
  - elseif
  - try
  - catch
  - switch
  - циклы с незакрытыми фигурными скобками.
- После выполнения команды окно не должно закрываться неожиданно.
- При необходимости добавлять Pause в конце самостоятельных сценариев.

### 5. Python
- После изменения любого .py-файла выполнять:
  python -m py_compile <имя_файла>

### 6. Backup
- Перед автоматическим изменением файлов создавать резервную копию (*.before_*).

### 7. Проверка
- Сначала проверка, потом изменение.
- При неоднозначности не выполнять рискованные действия.

### 8. Архитектура
- Не дублировать правила в нескольких документах.
- PROJECT_RULES.md является единым техническим сводом.
- CONSTITUTION.md описывает философию и обязательные принципы проекта.
- DAILY_START_CHECKLIST.md содержит только ежедневный чек-лист.

### 9. Типичные ошибки, которых нельзя допускать
- BOM в текстовых файлах.
- Markdown внутри JSON.
- Незакрытые if/else в PowerShell.
- Ошибки с Join-Path и дублированием сегментов пути.
- Частичная выдача команды вместо готового блока.


## ПРАВИЛО 11. ВОССТАНОВЛЕНИЕ ИЗ ТОЧЕК ОТКАТА

Перед любым ремонтом или переписыванием кода ОБЯЗАТЕЛЬНО:

1. Проверить наличие файлов:
   - *.before_*
   - *.bak
   - SNAPSHOTS
   - backup-копий.

2. Если существует подходящая резервная копия,
   сначала восстановить её.

3. Только при отсутствии пригодной точки отката
   разрешается выполнять ручной ремонт.

4. После восстановления выполнить:
   - python -m py_compile
   - лабораторные тесты
   - проверку памяти и чата.

## ПРАВИЛО 12. POWERSHELL БЕЗ ELSE

1. Все PowerShell-команды публикуются как самодостаточные блоки.
2. Запрещено использовать конструкции, требующие отдельного ввода else.
3. При необходимости используется ранний выход:
   - return
   - break
   - Pause
4. Запрещено публиковать незавершённые if/else.
5. Каждый блок должен корректно выполняться при копировании целиком.
6. После завершения вывода рекомендуется оставлять Pause отдельной строкой.


## ПРАВИЛО. ЛОКАЛЬНАЯ РАБОТА И СЕТЕВАЯ БЕЗОПАСНОСТЬ

1. Butler Omega имеет право работать с любыми локальными файлами и папками компьютера, если это необходимо для выполнения задачи пользователя.

2. Разрешается:
   - создание, чтение, изменение и перемещение локальных файлов;
   - создание папок и резервных копий;
   - анализ документов, изображений и других локальных данных;
   - использование локальных Git-команд, не требующих доступа в Интернет (например: git status).

3. Категорически запрещается без явного разрешения пользователя:
   - любые обращения в Интернет;
   - git pull;
   - git push;
   - git fetch;
   - git clone;
   - ollama pull;
   - автоматическая загрузка моделей;
   - автоматическое скачивание файлов;
   - обращения к внешним API и облачным сервисам;
   - любые иные сетевые операции.

4. При малейшем сомнении Butler обязан остановиться и запросить подтверждение пользователя до выполнения сетевого действия.
