# BUTLER DEPARTMENT RECOVERY

Рабочий документ восстановления Department.

Версия: 1.0
Дата: 2026-07-14

------------------------------------------------------------------

Данный документ НЕ изменяет архитектуру Butler.

Данный документ НЕ заменяет BUTLER_MASTER_ROADMAP.md.

Master Roadmap отвечает за стратегию проекта.

Recovery Document отвечает только за восстановление Department.

------------------------------------------------------------------

# ОБЩЕЕ ПРАВИЛО

Работа ведётся только по одному Department.

Переход к следующему Department запрещён,
пока предыдущий не получил пользовательский PASS.

После каждого шага обязательно выполняются:

- py_compile
- регрессионный тест
- пользовательская аттестация

Только после PASS работа продолжается.

==================================================================
ЭТАП 1
ВОССТАНОВЛЕНИЕ CodingDepartment
==================================================================

Статус:
[ ] Не начато
[ ] В работе
[x] PASS

Проблемы:

- пользовательская аттестация FAIL
- ответы моделей нерелевантны запросу
- часть моделей игнорирует инструкции
- иногда выдаётся общий текст вместо PowerShell
- отсутствует гарантированная проверка результата

Критерий завершения:

Пользовательские запросы должны выдавать корректный код.

Примеры:

- показать процессы по памяти
- поиск процесса
- работа с файлами
- работа с JSON
- работа с CSV

После успешной аттестации этап отмечается PASS.
